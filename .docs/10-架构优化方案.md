**当前采用的模式：**

## 2. 项目分层结构详解

### 2.1 表示层 (API Layer)

**职责范围：**
- HTTP请求接收和响应
- 参数验证（基础验证）
- 认证授权检查
- 异常格式化处理

**关键文件：**
- `UsersController.cs` - 用户管理端点
- `AuthController.cs` - 认证端点
- `ExceptionHandlingConfiguration.cs` - 全局异常处理

**依赖方向：**
```
Controllers → Application Services → Contracts → Infrastructure Implementations
     ↓              ↓                    ↓                ↓
  DTOs        AutoMapper           Interfaces         EF Core / Redis
```

### 2.2 应用层 (Application Layer)

**子模块划分：**

| 模块 | 路径 | 职责 |
|------|------|------|
| **DTOs** | `Application/DTOs/` | 数据传输对象定义 |
| **Mapping** | `Application/Mapping/` | AutoMapper映射配置 |
| **Services** | `Application/Services/` | 业务逻辑编排 |

**服务注册方式：**
```csharp
// ServiceConfiguration.cs - Scoped生命周期
services.AddScoped<IAuthService, AuthService>();
services.AddScoped<IUserService, UserService>();
services.AddScoped<IJwtService, JwtService>();
```

### 2.3 核心层 (Core Layer)

#### 2.3.1 契约层 (Contracts)

**接口清单：**
```
Contracts/
├── IRepository<T>           # 通用仓储接口
├── Cache/
│   └── ICacheService        # 缓存服务接口
├── User/
│   ├── IUserRepository      # 用户仓储接口
│   └── IUserService         # 用户服务接口
├── Auth/
│   └── IAuthService         # 认证服务接口
└── Jwt/
    └── IJwtService          # JWT服务接口
```

**设计问题：**
- ❌ 接口分散在不同目录，缺少统一命名空间
- ❌ 没有按聚合根(Aggregate Root)组织接口
- ❌ 缺少领域事件接口定义

#### 2.3.2 领域层 (Domain)

**实体结构：**
```
Domain/
├── BaseEntity.cs            # 基础实体（Id, CreatedAt, UpdatedAt）
└── User/
    └── UserEnitity.cs       # 用户实体（⚠️ 命名错误）
```

**实体特性：**
- 继承自 `BaseEntity`
- 包含审计字段（自动维护时间戳）
- 纯POCO对象，无行为方法

**缺失的领域概念：**
- ❌ 领域服务 (Domain Services)
- ❌ 值对象 (Value Objects)
- ❌ 领域事件 (Domain Events)
- ❌ 实体工厂 (Entity Factories)

#### 2.3.3 共享层 (Shared)

**组件列表：**
```
Shared/
├── Api/
│   ├── ApiResponse.cs       # API响应包装器（已重构✅）
│   └── ErrorResponse.cs     # 错误响应模型
└── Exception/
    ├── NotFoundException.cs  # 404异常
    └── BadRequestException.cs # 400异常
```

### 2.4 基础设施层 (Infrastructure Layer)

#### 2.4.1 数据访问层 (Data)

**实现层次：**
```
Data/
├── AppDbContext.cs          # EF Core上下文
├── EfCoreRepository.cs     # 泛型仓储实现
└── User/
    ├── UserRepository.cs    # 用户仓储实现
    └── UserConfig.cs        # 实体配置（Fluent API）
```

**⚠️ 关键问题：**
```csharp
// EfCoreRepository.cs - 当前实现
public async Task AddAsync(T entity)
{
    await _dbContext.Set<T>().AddAsync(entity);
    await _dbContext.SaveChangesAsync(); // ❌ 立即保存！
}
```

**影响：**
- 无法支持事务操作
- N+1查询问题风险
- 性能低下（每次CRUD都触发数据库往返）

#### 2.4.2 缓存层 (Caching)

**实现策略：**
```
Caching/
├── ICacheService.cs         # 接口定义（在Contracts中）
├── RedisCacheService.cs     # Redis实现
└── NoOpCacheService.cs      # 空操作实现（测试用）
```

**注册方式：**
```csharp
if (appSettings.Redis.Enabled)
{
    services.AddScoped<ICacheService, RedisCacheService>(); // Scoped
}
else
{
    services.AddScoped<ICacheService, NoOpCacheService>();  // Scoped
}
```

**问题：**
- Redis连接应为Singleton，但缓存服务为Scoped
- 缓存键硬编码在业务逻辑中
- 缺少缓存失效策略统一管理

#### 2.4.3 配置层 (Configuration)

**配置模型：**
```
AppSettings
├── ConnectionStrings: string?      # 数据库连接字符串
├── Jwt: JwtSettings?               # JWT配置
└── Redis: RedisSettings?           # Redis配置
```

**安全问题：**
- JWT密钥明文存储在appsettings.json中
- 无环境区分（开发/生产使用相同配置文件）

## 3. 依赖关系与调用链路

### 3.1 典型请求调用链路

#### 场景A：获取用户列表 (GET /api/users)

```
[1] HTTP Request
    ↓
[2] UsersController.GetAllUsers()
    ↓ 调用
[3] UserService.GetAllUsersAsync()
    ↓ 使用缓存装饰器
[4] CacheService.GetOrCreateAsync("users:all", factory, expiry)
    ├─ [4a] 缓存命中 → 直接返回
    └─ [4b] 缓存未命中 → 执行factory
        ↓
    [5] UserRepository.GetAllAsync()
        ↓
    [6] EfCoreRepository<User>.GetAllAsync()
        ↓
    [7] AppDbContext.Set<User>().ToListAsync()
        ↓
    [8] SQLite Database Query Execution
        ↓
    [9] 返回结果 → AutoMapper映射 → 包装为ApiResponse → HTTP Response
```

**性能瓶颈点：**
- Step [4b]: 每次都要检查缓存
- Step [7]: 无分页支持，可能返回大量数据
- Step [9]: 多次对象映射和包装

#### 场景B：创建用户 (POST /api/users)

```
[1] HTTP Request + UserCreateDto
    ↓
[2] UsersController.CreateUser(dto)
    ↓
[3] UserService.CreateUserAsync(dto)
    ├─ [3a] AutoMapper.Map<UserEnitity>(dto)
    ├─ [3b] HashPassword(dto.Password)        ← 密码哈希（应在独立服务中）
    ├─ [3c] UserRepository.AddAsync(user)     ← 触发SaveChanges() ❌
    └─ [3d] CacheService.RemoveAsync("users:all") ← 清除列表缓存
    ↓
[4] 返回 UserDto
```

**问题点：**
- Step [3b]: 密码哈希逻辑混入UserService
- Step [3c]: 立即保存数据库，无法回滚
- 缺少事务边界控制

### 3.3 依赖注入生命周期分析

| 服务类型 | 注册方式 | 生命周期 | 问题 |
|---------|---------|----------|------|
| **Controller** | 内置 | Transient/Scoped | ✅ 正确 |
| **Service** | AddScoped | Scoped | ✅ 正确 |
| **Repository** | AddScoped | Scoped | ⚠️ 应考虑Transient |
| **DbContext** | AddDbContext | Scoped (默认) | ✅ 正确 |
| **ICacheService** | AddScoped | Scoped | ⚠️ 可改为Singleton |
| **IConnectionMultiplexer** | AddSingleton | Singleton | ✅ 正确 |
| **AppSettings** | AddSingleton | Singleton | ✅ 正确 |
| **IMapper** | AddAutoMapper | Singleton | ✅ 正确 |

**潜在问题：**
- Repository为Scoped，但在同一请求中多次注入会获得同一实例
- 如果需要跨请求共享状态（如工作单元），Scoped是正确的

## 4. 核心问题诊断

### 🔴 P0 - 严重问题（必须立即修复）

#### 问题1：Repository立即保存破坏事务一致性

**位置：** 
- 文件：[EfCoreRepository.cs:48-52](../Chet.WebApi.Infrastructure/Chet.WebApi.Data/EfCoreRepository.cs#L48-L52)
- 影响范围：所有数据操作

**问题描述：**
```csharp
public async Task AddAsync(T entity)
{
    await _dbContext.Set<T>().AddAsync(entity);
    await _dbContext.SaveChangesAsync(); // ❌ 立即提交到数据库
}
```

**后果：**
- 无法在同一事务中执行多个操作
- Service层无法保证原子性
- 性能差（每个操作都是独立的数据库往返）

**实际影响场景：**
```csharp
// 创建用户时应该原子性完成，但现在分成多个独立事务
public async Task CreateUserAsync(UserCreateDto dto)
{
    var user = _mapper.Map<UserEnitity>(dto);
    user.PasswordHash = HashPassword(dto.Password);
    
    await _userRepository.AddAsync(user);           // 事务1：插入用户
    await _cacheService.RemoveAsync("users:all");    // 事务2：清除缓存
    
    // 如果清除缓存失败，用户已创建但缓存未更新 → 数据不一致
}
```

**解决方案：** 见第5章

```csharp
public interface IUnitOfWork : IDisposable
```

#### 问题5：Service层职责过重

**位置：** 
- 文件：[UserService.cs:95-100](../Chet.WebApi.Application/Chet.WebApi.Services/User/UserService.cs#L95-L100)

```csharp
// UserService 包含密码哈希逻辑（不属于用户管理职责）
private string HashPassword(string password)
{
    return BCrypt.Net.BCrypt.HashPassword(password);
}

}
```

**违反原则：**
- 单一职责原则(SRP)：密码处理应独立
- DRY原则：两个Service重复实现密码逻辑

**解决方案：** 提取 `IPasswordService`

## 5. 优化方案详细设计

### 5.1 Repository模式重构 🔴

#### 方案A：移除立即保存（推荐）

**目标：** 将持久化责任上移到Service层或UnitOfWork

**步骤1：修改IRepository接口**

```csharp
namespace Chet.WebApi.Contracts;

/// <summary>
/// 通用仓储接口 - 移除自动保存行为
/// </summary>
public interface IRepository<T> where T : class
{
    /// <summary>
    /// 根据ID获取实体
    /// </summary>
    Task<T?> GetByIdAsync(int id);

    /// <summary>
    /// 获取所有实体（慎用大数据集）
    /// </summary>
    Task<IEnumerable<T>> GetAllAsync();

    /// <summary>
    /// 将实体添加到上下文（不保存）
    /// </summary>
    Task AddAsync(T entity);

    /// <summary>
    /// 标记实体为修改状态（不保存）
    /// </summary>
    void Update(T entity);

    /// <summary>
    /// 标记实体为删除状态（不保存）
    /// </summary>
    void Delete(T entity);

    /// <summary>
```

### 5.2 工作单元(Unit of Work)模式引入 🟠

#### 设计方案

**步骤1：创建IUnitOfWork接口**

```csharp
namespace Chet.WebApi.Contracts;

/// <summary>
/// 工作单元接口 - 协调多个Repository的事务
/// </summary>
public interface IUnitOfWork : IDisposable
{
    /// <summary>
    /// 用户仓储
    /// </summary>
    IUserRepository Users { get; }

    /// <summary>
    /// 保存所有挂起的更改
    /// </summary>
    Task<int> SaveChangesAsync();

    /// <summary>
    /// 开始事务
    /// </summary>
    Task<IDbContextTransaction> BeginTransactionAsync(
        IsolationLevel isolationLevel = IsolationLevel.ReadCommitted,
        CancellationToken cancellationToken = default);

    /// <summary>
    /// 提交事务
    /// </summary>
    Task CommitAsync(CancellationToken cancellationToken = default);

    /// <summary>
    /// 回滚事务
    /// </summary>
    Task RollbackAsync(CancellationToken cancellationToken = default);
}
```

**步骤2：实现UnitOfWork**

```csharp
public class UnitOfWork : IUnitOfWork
{
    private readonly AppDbContext _context;
    private IDbContextTransaction? _transaction;
    private bool _disposed = false;

    public IUserRepository Users { get; }

    public UnitOfWork(AppDbContext context)
    {
        _context = context;
        Users = new UserRepository(context);
    }

    public async Task<int> SaveChangesAsync()
    {
        return await _context.SaveChangesAsync();
    }

    public async Task<IDbContextTransaction> BeginTransactionAsync(
        IsolationLevel isolationLevel = IsolationLevel.ReadCommitted,
        CancellationToken cancellationToken = default)
    {
        _transaction = await _context.Database.BeginTransactionAsync(isolationLevel, cancellationToken);
        return _transaction;
    }

    public async Task CommitAsync(CancellationToken cancellationToken = default)
    {
        try
        {
            await SaveChangesAsync(cancellationToken);
            await (_transaction?.CommitAsync(cancellationToken) ?? Task.CompletedTask);
        }
        catch
        {
            await RollbackAsync(cancellationToken);
            throw;
        }
    }

    public async Task RollbackAsync(CancellationToken cancellationToken = default)
    {
        if (_transaction != null)
        {
            await _transaction.RollbackAsync(cancellationToken);
        }
    }

    public void Dispose()
    {
        if (!_disposed)
        {
            _transaction?.Dispose();
            _disposed = true;
        }
    }
}
```

**步骤3：使用示例**

```csharp
// AuthService中使用事务
public async Task<JwtTokenDto> LoginAsync(LoginDto dto)
{
    using var transaction = await _unitOfWork.BeginTransactionAsync();
    
    try
    {
        var user = await _unitOfWork.Users.GetByEmailAsync(dto.Email);
        
        if (user == null || !_passwordService.Verify(dto.Password, user.PasswordHash))
        {
            throw new UnauthorizedAccessException("Invalid credentials");
        }

        var accessToken = _jwtService.GenerateAccessToken(user);
        var refreshToken = _jwtService.GenerateRefreshToken();

        user.RefreshToken = refreshToken;
        user.RefreshTokenExpiryTime = DateTime.UtcNow.AddDays(_appSettings.Jwt.RefreshTokenExpirationDays);
        
        _unitOfWork.Users.Update(user);
        await _unitOfWork.CommitAsync(); // 原子性提交

        return new JwtTokenDto { AccessToken = accessToken, RefreshToken = refreshToken };
    }
    catch
    {
        await _unitOfWork.RollbackAsync();
        throw;
    }
}
```

```csharp
using BCrypt.Net;

public class PasswordService : IPasswordService
{
    private const int WorkFactor = 12; // BCrypt工作因子（越高越安全但越慢）

    public string Hash(string password)
    {
        if (string.IsNullOrWhiteSpace(password))
            throw new ArgumentException("Password cannot be empty", nameof(password));

        if (password.Length < 6)
            throw new ArgumentException("Password must be at least 6 characters", nameof(password));

        return HashPassword(password, WorkFactor);
    }

    public bool Verify(string password, string hash)
    {
        if (string.IsNullOrWhiteSpace(password) || string.IsNullOrWhiteSpace(hash))
            return false;

        try
        {
            return Verify(password, hash);
        }
        catch
        {
            // 哈希格式无效时返回false而非抛出异常
            return false;
        }
    }
}
```

```csharp
        public static TimeSpan VeryLong => TimeSpan.FromDays(1);

    /// 用户相关缓存键

    {
        private const string Base = $"{Prefix}users";

        /// 通配符模式 - 用于批量删除

        /// 根据ID获取单个用户

        public static string ById(int id) => $"{Base}{Separator}{id}";

        /// <summary>
        /// 获取所有用户列表
        /// </summary>

    /// <summary>

        private const string Base = $"{Prefix}auth";

        /// <summary>
        /// Token黑名单

        /// <summary>

        /// </summary>
        public static string UserPermissions(int userId) => $"{Base}{Separator}permissions:{userId}";
    }
```

```csharp
// AuthService.cs - 重构后
public class AuthService : IAuthService
{
    private readonly IUnitOfWork _unitOfWork; // ✅ 使用工作单元
    private readonly IJwtService _jwtService;
    private readonly IPasswordService _passwordService; // ✅ 独立密码服务
    private readonly IMapper _mapper;
    private readonly ILogger<AuthService> _logger;

    public async Task<JwtTokenDto> LoginAsync(LoginDto dto)
    {
        _logger.LogInformation("Login attempt: {Email}", dto.Email);

        var user = await _unitOfWork.Users.GetByEmailAsync(dto.Email);
        
        if (user == null || !_passwordService.Verify(dto.Password, user.PasswordHash)) // ✅ 使用独立服务
        {
            _logger.LogWarning("Invalid login attempt: {Email}", dto.Email);
            throw new UnauthorizedAccessException("Invalid email or password");
        }

        // ✅ 开始事务
        using var transaction = await _unitOfWork.BeginTransactionAsync();
        
        try
        {
            var accessToken = _jwtService.GenerateAccessToken(user);
            var refreshToken = _jwtService.GenerateRefreshToken();

            user.RefreshToken = refreshToken;
            user.RefreshTokenExpiryTime = DateTime.UtcNow.AddDays(_appSettings.Jwt.RefreshTokenExpirationDays);
            
            _unitOfWork.Users.Update(user); // ✅ 只标记修改
            
            // ✅ 原子性提交（包括令牌生成和用户更新）
            await _unitOfWork.CommitAsync();

            _logger.LogInformation("Login successful: {Email}", dto.Email);
            
            return new JwtTokenDto 
            { 
                AccessToken = accessToken, 
                RefreshToken = refreshToken 
            };
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Login failed for: {Email}", dto.Email);
            await _unitOfWork.RollbackAsync(); // ✅ 出错时回滚
            throw;
        }
    }
}
```

**优势：**
- ✅ 完全原子性操作
- ✅ 失败时自动回滚
- ✅ 职责清晰分离
- ✅ 完善的错误处理和日志
